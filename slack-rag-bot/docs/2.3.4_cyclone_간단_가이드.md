# 2.3.4 cyclone 간단 가이드

## [Cyclone 기획자 가이드] 화면 명세(FR)를 읽기 전 필수 컨텍스트

### 1. 도메인 초보자를 위한 3분 비유 & 개념

* **제품의 본질**: 대기업 공장 안의 수많은 부서가 각자 따로 갖고 있는 데이터(데이터베이스, 엑셀 파일, AI 알고리즘 모델 등)를 한곳에 등록하고, 계보를 엮어주는 "데이터 도서관"입니다.
* **Medallion Architecture (Bronze/Silver/Gold) 비유**:
    * **Bronze (원석)**: 현장 센서에서 올라와 모래와 흙이 잔뜩 묻어 있는 원시 데이터.
    * **Silver (정제)**: 흙을 다 털어내고 결측치를 채워 깨끗하게 다듬은 가공 데이터.
    * **Gold (보석)**: AI 분석 엔진이나 대시보드에 즉시 활용 가능한 비즈니스용 핵심 결과 데이터.

### 2. Cyclone이 고객에게 돈이 되는 이유 (비즈니스 가치)

* **데이터 탐색 시간 99% 단축**: 대기업 연구원이나 엔지니어들이 "그 분석 데이터 어느 부서 누구한테 있어?"라며 수일 동안 메일과 전화를 돌려 찾던 것을 검색창 하나로 **수분 만에** 찾게 해줍니다.
* **잘못된 데이터 사용 비용 예방**: 오염되거나 신뢰도가 낮은 데이터를 가져다 AI 모델을 학습시키는 실수를 방지하여 수천만 원의 인건비 및 리소스 낭비를 막아줍니다.

### 3. 사용자 페르소나와 실무 시나리오

* **핵심 사용자**: 데이터 오너(도메인 담당 엔지니어)와 **데이터 분석가(소비자)**.
* **주요 시나리오**:
    * ① 데이터 분석가가 검색창(`FR-EXP`)에서 필요한 공정 온도를 검색 ➔ ② 상세 화면(`FR-DET`)에서 데이터 신뢰도 등급(Gold 인증)을 확인 ➔ ③ 데이터 계보(`FR-LIN`)를 통해 원천 소스가 맞는지 역추적 ➔ ④ 접근 권한 신청 후 다운로드.

### 4. 기획자 실무 협업 지도 (Who to talk to)

* **UI/UX 개선 및 모달 문구 수정**: 디자인팀(Figma 검토) 및 프론트엔드 개발팀 협의.
* **데이터 수집 상태 불일치 및 에러**: 데이터 엔지니어링팀 협의.
* **Trust Index(신뢰 지수) 및 자동 크롤러**: AI/알고리즘팀 및 백엔드 개발팀 협의.

### 5. 현재 버전의 한계 및 PM의 고민거리

* **컬럼 단위 권한 제어 불가**: 현재는 테이블 전체만 공개/비공개가 가능하여, "특정 민감 컬럼(예: 원가, 직원정보)만 가리고 보여달라"는 고객사(에스엘 등) 요구에 기획적 대안이 필요합니다.
* **수동 계보(Lineage) 신뢰성**: 사용자가 화면에서 계보를 수동으로 연결할 수 있는데, 잘못된 연결을 방지할 검증 체계(Domain Admin 승인 프로세스 등)를 기획해야 합니다.
